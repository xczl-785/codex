# 前置检查与实际执行限制的连接

用户通过脚本先写允许目录、再写禁止目录的场景理解了执行前准入、带权限启动和实际访问约束。随后主动提出：特化工具能预先知道副作用范围，是否因此与 Shell 不同。并排核对补丁目标检查与 Shell 命令规则后，用户复述确认：“只是在最后仍然要保留执行限制，因为前置检查并不能完全防范。”这支持其已理解前置目标更明确与执行层仍须落实限制可以同时成立，不等于已独立验收工程。

最初讲解一次引入注册表、共享编排与具体执行器，未直接说明两条链的判断对象差异。用户追问不代表遗忘旧权限实验。后续先给同一目标的两条具体路径，再引入源码结构；肯定用户抓住的差异，并区分“知道目标”“有权操作”和“执行时落实权限”。稳定内容见[课程 0038](../lessons/0038-permission-admission-and-execution.md)。不必再次从头解释补丁与 Shell。

用户随后追问指定目录的额外权限如何从申请变为批准记录，明确只需简单了解实现逻辑。按“结构化申请 → 决定绑定申请 → 合成本次权限 → 后端落实”讲解后，用户表示理解并要求继续。这属于理解反馈，不是独立实现证据；后续进入执行后端映射，不展开全部缓存和持久化字段。
