# 区分验证能力与模型判断

用户在理解文件冲突、撤销与历史重建后，主动指出验证讲解混合了两个角度：“Agent 可以提供什么工具，LLM 怎么判断”。据此将讲解修正为宿主提供执行与观察能力、验证程序判定既定规则、LLM 选择检查并解释任务覆盖范围三层。用户认可并要求整理后继续。

这表明用户已能用职责边界检查教学叙述，而不只是接受流程。后续协作与转型讨论应明确哪些是宿主能力、哪些是提示与模型策略、哪些属于需要额外实现的强制门禁。不要把合理的模型行为描述成当前源码已保证。稳定解释见[课程 0033](../lessons/0033-verification-tools-and-model-judgment.md)；本记录不表示目标工程已实现专用验证工具或交付门禁。

用户随后将同一分析迁移到子 Agent 修改面：实际使用中主要由主 Agent 分工、约束，追问 Harness 是否提供硬限制。源码核对后明确常规委派链路的权限接续与模型分工是两层，worker 行为指令不自动成为文件权限。用户确认理解。后续应先报告实际保证，再讨论模型策略与可选增强；见[课程 0034](../lessons/0034-subagent-writes-and-integration.md)。

用户继续追问 Plan 模式的实际机制，确认理解只读契约与协作模式的区别，要求记录并保持当前模式继续学习。静态核对与边界见[课程 0035](../lessons/0035-read-only-contract-and-plan-mode.md)；没有实际切换模式或验证当前客户端界面。
