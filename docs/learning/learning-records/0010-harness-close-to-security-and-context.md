# 学习记录 0010：从 Harness 实践收尾转入权限与上下文专题

## 阶段变化

独立 CodebaseAgent 的核心测试已经通过，用户正在完成最后的文档收尾。实践已实际覆盖确定性模型—工具循环、真实 Provider、持久 Thread、新 Session 恢复、显式压缩检查点、上下文容量边界和真实仓库走查。

这取代学习记录 0009 中“刚转入实践准备”的当前阶段描述。实践 0001 的原始目标和边界仍有效，但实时实现状态只由独立工程自己的 `docs/STATUS.md` 维护。

## 当前理解基线

- 用户对权限、审批和沙箱已经有大致认识，知道沙箱不是模拟副本，提权也不能等同于所有失败的通用重试。
- 当前薄弱点是无法稳定、完整地复述 Policy、Approval、Sandbox、Escalation、执行尝试、真实进程和失败分类的先后关系；回答具体场景时容易漏掉一层。
- 用户通过 CodebaseAgent 已接触上下文限制、压缩和历史恢复，但实践主要围绕 Harness 主题和模块边界推进，没有打算深入每个生产级子系统。
- 用户希望继续采用“宏观结构 → 具体场景 → 必要源码对照 → 小型实践”的方式，不追求把所有平台细节和优化算法一次学完。

## 后续顺序

1. 实践 0002：权限、审批、沙箱与提权；
2. 实践 0003：上下文限制、压缩检查点与历史恢复复盘；
3. 取消传播；
4. 并行工具调度；
5. Subagent 生命周期与通信。

权限先于取消，是因为它负责动作准入；取消负责已开始动作的停止和清理。上下文复盘排在二者之间，是为了趁 CodebaseAgent M3 经验仍新鲜时完成概念吸收，而不是因为它是取消的技术前置。

## 深度决定

### 权限与沙箱

深入控制面、不变量、失败路径和重试边界；中等深度阅读 Codex 编排源码和测试；只认识平台沙箱实现的责任与入口，不手写安全级 OS 沙箱。

### 上下文、压缩与恢复

深入持久事实、运行投影、模型可见性、checkpoint 和恢复语义；中等深度追踪 Codex 关键调用链；暂缓 tokenizer、摘要质量、向量记忆、分布式持久化和生产容量优化，直到真实故障提供进入条件。

## 教学衔接

下一位 Agent 不应重新泛讲“什么是权限”或完整复述课程 0007/0009/0012。应分别从一个会出错的具体场景开始，让用户先判断：

- 动作是否获准、进程是否创建、副作用是否可能发生、能否重试；
- 某条信息是否仍保存、是否进入当前 Prompt、是否可检索、恢复后由谁重建。

再根据回答缺口回到源码和确定性实验。
