# 面向 Agent 的工具与通用权限边界

用户识别出转型课程中的权限部分是既有沙箱与权限知识的具象化，并追问为何存在补丁专用类、patch 是否是所有修改的统一接口。讲解最初直接解释专用类职责，遗漏了 patch 在全部修改路径中的位置；此处是教学边界未交代清楚，不能归因于用户遗忘权限知识。

明确 patch 只是修改方式之一、通用资源约束仍在底层之后，用户主动提出 agent native 的解释：接口面向 Agent 使用，为编码场景中频繁的修改操作提供直接、便利的表达。进一步讲解了对模型和宿主的双向收益，用户要求记录并继续。该反馈支持其已能从工具使用者与任务场景理解接口设计，不据此推断独立实现或长期熟练。

后续可以从“专用任务操作复用通用权限和执行设施”起讲，不重讲整套权限基础；介绍具体类之前先定位它覆盖哪些操作、哪些路径不经过它。便利性不等于执行速度已测量，工具频率也无统计证据。稳定解释见[课程 0031](../lessons/0031-coding-agent-tools-and-permission-boundaries.md)。
