## 怎样理解难度与记忆深度

难度是教学判断：低为单条直观链路，中为多个概念或边界，高为多生命周期、失败和竞态交叉。它不表示学习者能力高低。

记忆深度依据记录 0001—0014、[历史教学笔记](history/teaching-notes-through-2026-09-20.md)及既有复盘，不是本轮无提示测试。使用四种标注：

- **可迁移**：曾主动提出设计判断，或能用新场景解释；不代表细节永久记住。
- **场景掌握**：有正确复述或场景判断的证据，尚不能据此推断独立源码定位能力。
- **重点巩固**：有明确漏层、混淆或纠正记录；可能已经理解，仍值得隔一段时间复述。
- **证据有限 / 未学**：缺少该课单独检验记录，或没有展开课程；不等于不会。

反复提问可能来自遗忘、边界难分、继续深入，也可能是此前讲解不准确。尤其取消专题曾由教师纠正对进程管理器的过度概括，不能把所有反复都归因于学习者记忆差。没有完整逐轮统计，不编造提问次数或掌握百分比。

## 把已学内容串成一个流程

先看职责与状态流，不按课号机械重读。以下是已有课程的复习提纲，架构细节仍以课程和当前源码为准。

1. **接到输入**：CLI、TUI 或客户端提交操作。已有 Thread 保留长期身份，Session 承载当前运行；空闲时启动 Turn，活动时可能 Steer 或等待。对应 0001—0003。
2. **开始执行**：Task 承担这一轮的具体执行，内部可以经历多次 Step。长任务并不因工具调用多就变成多个 Turn。对应 0006、0008。
3. **准备模型请求**：把历史、指令和当前工具视图组装成一次请求。Step 内工具说明与执行 Router 要一致；跨 Step 才讨论能力变化。对应 0009—0011。
4. **模型提出工具调用**：Harness 解析和校验调用，按权限、策略与审批边界决定能否执行，再由沙箱或执行后端落实限制；结果、拒绝和错误进入反馈闭环。对应 0010—0012。
5. **执行与等待结果**：Tool Call 和真实进程拥有不同生命周期；yield 允许之后续接。多个调用还要分别判断并行资格、业务依赖、真实完成与历史记录顺序。对应 0014、0015、0018。
6. **记录并继续**：Call/Output 保留因果配对，工具输出进入模型历史，下一次采样继续。历史太长时可能压缩有效投影；持久保存与当前模型可见范围不同。对应 0007、0009、0011、0016。
7. **遇到取消或重启**：取消停止执行推进，但不会撤销已发生的副作用；恢复重建运行投影，未知结果先核验。Fork、Revert、文件恢复也必须分层判断。对应 0005、0013、0016、0017。
8. **向下一专题延伸**：Subagent 将上述主链放到子 Thread 中，同时引入父子关系、通信、等待与回收；A2A 进一步提出跨系统的状态和协作边界。具体机制留待课程核对。

## 优先复习的三个连接点

不重新安排整轮考试。开课前可各取一个短场景，回答顺畅就直接进入新主题：

- **权限链**：报告已经生成，但复制到工作区外被拒绝。先判断哪一步发生、哪些副作用保留，再区分资源授权、命令规则与是否值得重试。重点复习 0012。
- **恢复链**：历史为 A → H₁ → B → H₂ → C，C 中一次写入没有 Output。区分恢复基线、当前可见范围与未知外部结果。重点复习 0007、0009、0016。
- **生命周期链**：一个调用已返回 session_id，另一个正在执行，此时取消 Turn。分别判断 Call、Turn、进程和副作用，而不是只给一个 cancelled。重点复习 0014、0017、0018。

后续掌握程度应以新的无提示复述更新，不把本表变成固定标签。Skills 和 MCP 课程还会自然复用 Step 快照、指令上下文、权限与连接生命周期，不必先背完所有旧细节。
