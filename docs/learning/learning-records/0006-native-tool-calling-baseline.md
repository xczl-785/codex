# 学习记录 0006：原生 Tool Calling 已成为理解基线

## 用户已有认识

用户知道传统 Agent 设计经常讨论“怎样让模型稳定输出合法 JSON”，并观察到现代模型通常已经提供原生结构化输出或工具调用能力。

这意味着后续教学不需要长时间停留在 Prompt 提取 JSON 的早期实现，而应重点区分：

- 普通文本中的 JSON；
- JSON mode；
- JSON Schema / Structured Outputs；
- Function Calling / Tool Calling；
- Harness 运行时校验。

## 本轮修正后的认识

模型平台的结构化能力主要减少语法和结构错误，不负责保证：

- 工具真的存在；
- 参数在当前环境中有意义；
- 操作已获得用户授权；
- 执行一定成功；
- 工具选择能够解决当前任务。

因此现代 Agent 的重点已经从“正则提取 JSON”转向“结构化协议、信任边界、错误反馈与自我修正闭环”。

## 后续教学方向

- 继续沿一次 Step 的模型采样、工具分发、结果写回和下一次采样阅读源码。
- 讲工具路由时优先解释工具发现、工具身份和 `call_id`，再进入具体 Handler。
- 讲审批和沙箱时始终强调：Schema 合法不等于执行合法。
