# 学习记录 0014：并行准入、结果顺序与职责分离

用户已经掌握工具并行能力声明、具体调用依赖和结果汇集顺序属于不同问题。后续并行实践可以从有界调度和确定性竞态测试开始，不必再从“同一种工具能否同时调用”这一层重新建立概念。

## 理解证据

- 用户能说明两个不同工具也可能并行；是否同名不是判断依据，关键是各处理器的能力声明和运行框架门禁。
- 用户明确指出工具允许并行不消除场景中的顺序依赖：若 B 必须验证 A 的结果，模型或工作流应顺序产生调用，由 Harness 执行已经表达出的依赖。
- 用户把模型、Harness、工具概括为标准职责分离，并认识到各层无需承担职责外的业务冲突推断。
- 在慢 A、快 B 场景中，用户正确给出真实完成顺序可能为 B、A，而结果按 A、B 写入对话历史；下一次模型请求需等待队首与整批结果收口。
- 在取消并行批次场景中，用户能够区分已完成结果、未完成调用和外部副作用，理解当前 Turn 不会根据部分结果继续采样。

## 对后续教学的影响

- 实践应使用 barrier、channel 或显式 gate 证明真实重叠、并发上限和完成顺序，不用睡眠时间猜测。
- CodebaseAgent 先固定取消语义，再放开 `max_parallel_tool_calls > 1`；并行阶段重点验证共享/独占准入、`call_id` 配对、稳定历史顺序和批次屏障。
- 暂不引入资源路径冲突分析、通用 DAG 或 Subagent 并行；这些需要新的真实需求和独立契约。
