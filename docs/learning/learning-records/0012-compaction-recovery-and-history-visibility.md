# 学习记录 0012：压缩、恢复与历史可见性

用户已经能够把持久事实、Session 运行态 History、当前模型可见历史和按需检索能力分开。后续教学不需要再从“压缩是不是删除旧对话”讲起，可以直接讨论检查点选择、恢复投影、结果未知与安全重试。

## 理解证据

- 在“旧历史 A → H₁ → B → H₂ → C”的恢复场景中，用户确认应以 H₂ 为基线接上 C，并指出这才是新 Session 的模型可见历史区间。
- 用户指出按需读取持久历史不代表原文仍在当前可见历史，也不代表 Agent 每次都会主动检索；能否找回取决于工具的作用范围和查询机制。
- 用户能够区分“配置修改成功、随后压缩失败”这两个独立事实，并提出恢复后应先核验文件现状。
- 对缺失 FunctionCallOutput 的场景，用户认识到合成中断标记用于补全历史结构，不能证明外部副作用没有发生。
- 用户指出重新读取通常没有重复写入风险，但第二次结果可能因外部文件变化而不同。

## 对后续教学的影响

- 不再把“保存、当前可见、可检索”作为新概念重复讲解，后续用具体恢复或重试场景检验边界即可。
- 讨论压缩失败时，应同时说明当前执行路径如何退出、Provider 硬上限仍然存在，以及已完成外部事实不会回滚。
- 历史恢复练习可以提升到部分提交、幂等核验和并发修改，不必停留在摘要是否无损。
