# Skills 整体回顾：从任务到结果

覆盖课程 0025—0030。目标是把机制放回一次真实任务，优先记职责、因果和失败边界；源码符号用于查阅。本回顾不表示接入实践完成，也不替代学习者的独立实现证据。

## 1. 先记一句定义和四条主线

Skill 是可发现、按需读取的任务方法包，可以带参考资料、脚本和模板；模型理解其指令，工具执行具体动作，宿主维护上下文与执行边界。

```text
发现有哪些 → 选择用哪个 → 内容进入上下文 → 通过工具执行并验证
```

Skill 不是一个自带独立进程、天然权限或确定性步骤调度器的对象。

## 2. 用恢复分析任务走完主链

用户要求用 recovery-analysis 分析 Project 的恢复机制。

### 发现

宿主依据 cwd、配置及来源确定扫描根，读取元信息。Project/.agents/skills 在根目录工作时可被扫描；Project/module/.agents/skills 不会仅因处于项目内部就被根目录会话发现。以 module 为发现 cwd 时，其祖先链可同时带入项目公共和模块能力。根内部递归与全项目向下找根是两回事。

名称适合展示，路径或资源 ID 用于身份。不同路径同名不等于自动覆盖。候选清单不是所有正文。

### 选择

用户显式指定时，结构化名称加路径可准确定位；只收到裸名称时要按对应入口处理歧义和冲突。界面手打也可能由客户端补为结构化输入，不能仅凭视觉文本推断后端数据。

没有明确指定时，模型可根据候选描述选择并读取。隐式使用检测是对已提出的读取或执行请求做归属，不是替模型作选择的关键词引擎。

enabled=false 与 allow_implicit_invocation=false 不同：前者影响正常选择资格，后者允许显式使用而隐藏默认候选提示。它们都不是文件访问权限。

### 加载与上下文

选中后读取正文，处理失败、预算及重复注入。显式正文在当前实现中可以是带 skill 标记的 user 消息；自主通过工具读取的正文通常在工具结果中。来源会影响具体读取和长度策略，不能用单一限制概括全部路径。

正文提供共同方法与关键约束；references 提供按分支读取的详细知识；scripts 处理机械步骤；assets 支持产物；agents/openai.yaml 提供宿主/UI 相关配置，不是创建子 Agent 的开关。

### 执行和验证

模型根据正文定位持久化与恢复入口，调用现有读取或搜索工具。调用和结果通过 call_id 关联并进入历史。脚本执行仍取决于工具、解释器、环境及权限。使用事件可能早于执行，不能证明读取成功、模型遵守指令或结果正确。

最终结论要区分源码推断、测试证据和实际运行观察。比较使用 Skill 前后的判断质量，而不只看输出长度。

## 3. 为什么会连到上下文

模型不会直接感知磁盘、宿主状态或权限变化，必须由输入告知。因此 Skill 的存在、选中、正文和工具结果分别进入不同状态。

| 对象 | 含义 | 不可推导的结论 |
| --- | --- | --- |
| 磁盘文件 | 当前保存的资料 | 模型已读到最新版 |
| 发现快照 | 当前知道的候选身份及元信息 | 所有正文冻结或已加载 |
| 本次选择 | 明确选中的资源 | 读取一定成功 |
| 历史正文 | 曾经读入的具体文本 | 当前任务仍适用或永久可见 |
| 使用事件 | 识别到相关行为请求 | 执行成功或任务成功 |

文件改为 V2，不会自动把历史 V1 改写；目录刷新不等于正文重读。禁用或删除不能撤回已有历史。压缩后应检查实际重建上下文，恢复清单不等于恢复每份完整正文。

每次请求重新组装不等于每次重扫文件，也不等于内容变化。world state 用当前状态与基线比较，把必要更新记入历史；Skill 更新可以是整段新清单，不必逐行差分。

本地发现缓存与服务端提示缓存不同。提示前缀若在早期被改写，后续同样文本也不能跨越差异继续作为同一连续前缀；追加更新有助于保持旧前缀，但不保证命中。实际复用量看响应指标。

增量工具模式让声明通过 AdditionalTools 进入历史；当前 Codex 新窗口要求 Responses Lite 和相应开关。普通 Chat/Responses 也能同步环境和 Skill 变化、更新顶层工具集合，只是不能直接照搬 Lite 声明载体。上下文增量、网络传输增量和提示缓存是三回事。

## 4. 设计与扩展的边界

AGENTS.md 保存项目约定，Skill 提供任务方法，工具/宿主实现必须强制检查的条件。项目专用 Skill 也合理；两份自然语言指令都不是操作系统权限。

多 Skill 组合应有明确输入输出，例如恢复分析产生证据，文档 Skill 整理成果；不要都接管所有流程。加载顺序不自动构成冲突优先级。

子 Agent 的历史继承、能力发现和执行权限独立判断。远端 Skill 保持来源、包和资源身份，通过对应 Provider 读取。插件是交付方式，不等于远端；声明依赖不等于已经获得工具或授权。

## 5. 到实践时应该验证什么

先验证发现、身份选择、正文加载与请求结构，再验证历史延续、变化和失败路径，最后用真实任务评估选择及结果质量。不能因模型回答了就宣告接入完成。

保留目标工程当前能力契约。Skills 接入不自动增加写入或命令权限，不提前开始标准 code agent 转型。顺序仍为 Skills 课程与回顾 → Skills 接入实践 → CodebaseAgent 转型课程 → 转型任务书与实践。
