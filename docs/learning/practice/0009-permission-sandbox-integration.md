## 3. 本次目标与贯穿场景

在 CodebaseAgent 内贯通以下职责链，并使模型和用户获得准确结果：

```text
正常工具调用
  → 理解操作与权限请求
  → 准入判断及必要审批
  → 本次有效权限
  → 后端落实约定限制并执行
  → 取消、退出与结果处理
  → 结果回到原有工具历史及模型循环
```

贯穿案例：在允许目录追加日志、生成报告，再尝试复制到未获准目录。观察拒绝发生在哪一步、已经保留哪些产物、是否需要申请权限，以及是否可以只重试复制。示例路径和命令应使用隔离测试夹具，不对真实用户数据做破坏性验证。

复用现有 Model—Tool 循环、调用身份、调度、历史、取消信号、Skills 与协作基础；已有取消信号不等于真实进程已能终止，已有路径检查不等于任意脚本已经受限。实际可复用部分以目标工程当时的实现为准。

## 4. 技术选择留给目标工程

首先讨论运行平台与资源边界：原生 Windows、WSL/Linux 或其他执行环境；文件读写、网络、子进程与宿主资源分别承诺限制什么。学习环境是 Windows，但本文件不替用户选定运行平台。

然后讨论真实后端来源及集成成本：

- 调用已安装的 Codex 沙箱命令，是外部程序依赖，不等于复用 Codex 的模型或整个 Agent；需要明确版本、配置隔离、权限传递、输出、取消和部署契约。
- 提取或集成 Codex 内部实现，需要核对内部依赖、辅助程序、许可及维护成本；不能假设某个 crate 是可直接引用的独立通用组件。
- 接入其他独立后端或平台设施，需要验证其实际支持的资源限制与生命周期；不因名称含“沙箱”就视为满足需求。

以上是需比较的技术类别，不是已接受方案。**本实践不要求依赖 Codex，也不要求从零编写安全级操作系统隔离机制。** 控制面由 CodebaseAgent 拥有，适配层把有效权限转成后端配置，强制限制依靠选定执行设施。确定后端后再安排真实路径验证与完整 Agent 集成的实施顺序。

## 5. 已学机制与设计检查点

### 准入与真实操作覆盖

补丁等特化工具能提前列出明确目标，Shell 通常先按命令规则和权限请求判断；不能普遍提前列出脚本全部访问。前置检查不替代执行约束。共享审批与编排不意味着所有工具执行方式相同，也不要求照搬 Codex 类型组织。

列清本轮开放的文件访问、命令、脚本和其他执行入口及其约束落点。宿主直接写文件不能因子进程受限就被视为自动受限。Skill 指令和子 Agent 分工不授予额外权限；若开放相关执行路径，须有真实覆盖。

### 审批、有效权限与授权时效

申请用结构化数据表达操作、资源范围和作用域，解释原因不代替权限字段。批准绑定原请求；请求改变不能静默沿用旧批准。批准普通执行不自动扩大资源范围；获批额外权限则须准确传到执行端，并保留不能被普通审批覆盖的限制。

区分本次执行权限、审批历史、可复用授权与持久规则。目标工程确定作用域、匹配条件和失效方式，不机械照搬旧实验 Turn/Session 或课程的一次性示例。历史里存在批准事实不自动成为新调用授权；工具返回不一定意味着进程结束或权限已撤销。

### 执行、审批等待与取消

权限数据需转换成实际约束；承诺受限执行却无法建立限制时，应报告失败，不静默普通执行。说明后端不支持某项资源限制时如何处理，不用未验证限制作产品承诺。

等待审批时取消，应使原请求收口，迟到批准不能启动已取消任务。执行时取消，应传到真实执行拥有者，按契约管理进程及相关子进程；停止等待输出不等于停止执行。输出限制、超时、清理和退出状态与现有生命周期协调。

### 失败、变更与恢复

区分执行前拒绝、准备失败、运行中资源拒绝、普通命令错误、取消及结果未知。失败不代表没有修改，沙箱不是事务回滚。Harness 报告可可靠观察的事实；任意脚本的全部副作用未必可知，不能编造“没有变更”。

若设计自动重试，需要明确适用错误、上次执行是否结束、副作用证据和次数边界；不得因权限不足就无条件重跑整个非幂等操作。持久恢复不能因结果缺失而自动重放旧调用。

## 6. 验证场景参考

目标工程根据选定能力细化验收；下表不要求扩展出尚未选择的功能，但已承诺的限制须有真实证据，Fake 结果不能替代。

| 场景 | 需要核对的事实 |
| --- | --- |
| 默认允许范围内访问 | 真实操作成功，产物和输出正确 |
| 明确禁止的动作、审批拒绝 | 本次目标操作没有启动，原因准确返回 |
| 批准额外范围 | 获批范围生效，未获批范围仍按约定受限 |
| 先成功后越界 | 后续访问被拒绝，前序副作用保留并准确表达 |
| 审批等待时取消、迟到批准 | 请求结束，不再启动原操作 |
| 执行期间取消或超时 | 实际执行生命周期与报告一致，不假定自动回滚 |
| 沙箱不可用或权限不可表达 | 明确失败，不静默放宽限制 |
| 命令不存在、参数错误等普通失败 | 不误报为权限问题，不无条件提权 |
| 若支持授权复用 | 范围变化、作用域结束及恢复后均按契约匹配 |
| 若支持子进程、网络或特殊路径 | 分别验证子进程限制、网络边界、链接与保护路径，不用普通文件样例代替 |
| 经正常工具入口执行并返回 | 调用与结果关联，模型、界面和历史获得准确状态 |

可用固定请求、ScriptedModel、fixture 和可控取消时点减少模型随机性；仍需经实际后端验证资源限制，最终按目标工程安排观察正常 Agent 使用。测试方式不规定实施阶段。

## 7. 与编码实践的分界及交付

本实践提供后续编码能力消费的准入、授权与受控执行基础。为验证限制所做的固定写入或进程探针，不等于已经完成[编码实践 0008](0008-coding-agent-integration.md)的编辑工具、冲突处理、差异观察和修改—验证闭环。具体工具和共享责任划分在目标工程确定，避免两项实践各自维护绕过彼此的执行路径。

目标工程维护最终范围、选型理由、行为契约、实现、测试、体验及未验证边界。交付时应能说明采用什么后端、实际限制什么、所有开放入口怎样经过权限流程，以及拒绝、取消和部分失败如何反馈。技术验证、用户体验与学习理解分别说明。

权限接入按目标工程约定验收后，再复核 0008 前置条件并进入编码实践。学习仓库只接收教学反馈和更新衔接，不镜像目标工程进度或凭任务书存在宣布接入完成。
