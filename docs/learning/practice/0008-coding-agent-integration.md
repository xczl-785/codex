# 实践任务书 0008：编码能力接入

## 用途、状态与前置条件

本任务书交接课程 0031—0037 已讲内容：将只读代码理解 Agent 扩展为能修改代码、执行检查并解释结果的 Agent。用户于 2026-10-28 要求先形成任务书，安排在权限与沙箱正式接入实践之后。

**状态：已准备，等待前置实践验收；不启动实施。** 编号表示材料身份，不表示执行顺序。权限与沙箱接入将单独教学、形成任务书并验收；旧实践 0002 的独立实验完成不能代替正式接入。

进入本实践前，应在目标工程核对：实际工具路径已有动作准入和授权机制；约定平台的受控进程执行、输出、超时、取消及拒绝反馈已经贯通；学习者已完成该项实践验收。权限边界以目标工程实际契约和证据为准，不以存在配置项或审批按钮作为完成依据。

目标工程为 CodebaseAgent。接手者先读其 AGENTS、工作流、STATUS、能力文档和契约。当前能力、实施范围、阶段、设计、测试及验收证据由目标工程拥有；本文件提供课程输入和验证参考，不复制实时状态，不预设必须照搬 Codex 类型或补丁格式。

## 一、贯穿任务

用户要求修复一个代码问题，仓库中已经有用户的未提交修改。Agent 读取并定位原因，提出和执行局部修改，运行相关检查，根据结果修正或交付。

实践需要让学习者解释：哪些是模型作出的选择，哪些是 Harness 的强制行为；实际修改和验证结果如何进入模型上下文与用户视图；失败、取消和恢复后如何保留准确事实。

## 二、复用基础与新增责任

| 类别 | 交接内容 |
| --- | --- |
| 既有运行底座 | Model—Tool 循环、工具注册、Call/Output、历史与压缩、恢复、调度、Skills 和协作；开始时核对实际现状 |
| 前置实践交付 | 权限准入、审批与受控执行设施、基本进程管理；本实践消费这些能力，不另造一条绕过路径 |

| 仍属模型判断 | 定位原因、生成修改、选择测试、解释覆盖程度、协调任务及决定下一步 |

文件编辑可能在 Harness 进程中直接发生，不能因为 shell 已受沙箱约束，就认为编辑接口自动获准或受限。编辑接口仍须接入公共授权，并落实自身路径和写入规则。

## 三、应在目标工程回答的设计问题

### 修改接口与当前文件状态

选择补丁、精确替换或其他表达时，说明它如何匹配当前内容，怎样报告匹配失败、文件不存在、编码问题和写入失败。新增文件、删除或重命名是否进入本轮范围，由实际场景确定。

说明一次请求跨多个文件时的部分完成语义。若没有事务或回滚能力，就应返回已完成与未完成部分，不能将整体失败表达为毫无变更。若要求避免覆盖过时内容，应给出实际前置条件检查，不能只依赖“先读再改”的提示。

### 权限与并发

明确只读模式与编码模式的实际能力差异，修改工具和进程执行都必须服从有效权限。审批授权不得超出其作用域。具体保护路径、配置方式和模式切换由目标工程定义。

明确写入工具的调度作用域；已有 Exclusive 声明不自动等于跨会话或整个文件系统的锁。可先完成单 Agent 编码闭环；是否开放子方写入由目标工程另行决定，任务分工文本不能冒充硬权限。

### 观察、验证与交付

模型和用户都应能获取实际变更与检查依据。工作区原有差异不等于本轮修改，不能从总 diff 自动推断归属。验证结果应能对应执行时的工作目录、命令、退出状态与输出；后续代码变化可能使先前结果失效。

模型负责选择检查并判断需求覆盖。若目标工程要求强制交付门禁，应单独定义程序规则，不把提示词或最终报告当作门禁实现。

### 取消与恢复

区分执行状态、修改状态和验证状态。取消不得被解释成自动撤销。已完成的修改可能与未完成的验证同时存在。

结果缺失时保留未知，不自动重放可能产生副作用的调用。复用既有历史和恢复能力时，核对新增工具的结果分类、持久化失败及迟到结果是否仍满足契约。历史可帮助重建，但不承诺完整文件备份。

## 四、验证场景参考

以下用于在目标工程选取、细化验收，不是无条件要求全部实现：

| 场景 | 核对的问题 |
| --- | --- |
| 正常局部修改与检查 | 变更真实发生，检查结果进入上下文和用户视图 |
| 仓库已有用户修改 | 不覆盖、不误归属，不用整仓回滚替代局部处理 |
| 修改前文件发生变化 | 拒绝、重新读取或其他已定义策略得到正确执行 |
| 权限拒绝或审批取消 | 未获准动作不执行，失败原因准确回传 |
| 跨文件部分失败 | 已发生的修改可观察，不报告为全部未执行 |
| 检查失败或超时 | 不把工具失败等同于代码错误或没有副作用 |
| 修改完成后用户取消 | 文件状态与验证状态分别表达 |
| 结果落盘前中断并恢复 | 保留未知，不自动重放旧修改 |
| 检查后又修改代码 | 不把旧结果当作新版已验证 |
| 若开放子 Agent 写入 | 核对真实权限、并发作用域与组合后检查，不只看完成报告 |

## 五、非前置完整性与交付归属

完整 Plan 模式、跨文件事务、全仓快照、通用自动重试、后台进程持久恢复、子 Agent 并行写入和自动 Git/PR 交付都不因本任务书自动成为要求。需要时由目标工程根据实际问题决定。

交付应能解释选定的修改链路、权限落点、失败结果与验证证据。目标工程维护最终范围、测试结果、遗留问题和用户体验验收；学习仓库只记录理解与下一教学方向。
