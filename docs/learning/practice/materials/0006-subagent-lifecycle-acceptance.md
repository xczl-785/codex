# 0006：Subagent 生命周期验收材料

本文固定[实践 0006](../0006-subagent-lifecycle-lab.md)的验证问题和证据要求；实施范围、阶段及进入条件由实践入口维护。以下是 CodebaseAgent 实验要求，不是对 Codex 每个实现分支的保证。

## M0.5 前置验收：单 Agent Steer

先在没有子 Agent 的场景验证公共执行机制。以下是实验契约，不能据此声称当前 Codex 或 CodebaseAgent 已通过验证。

| 编号 | 场景 | 必须观察到的事实 |
| --- | --- | --- |
| P1 | Turn T 正在只读工具 gate 等待时，提交针对 T 的补充要求 | 接收返回不等待工具或业务完成；Thread/Turn 不变；释放 gate 后捕获的后续模型请求包含该输入，工具 Call/Output 仍配对 |
| P2 | Thread 空闲，或活动 T2 收到预期 T1 的严格 Steer | 明确拒绝；不启动新 Turn，不将输入交给 T2；调用方保留失败输入并可决定后续动作 |
| P3 | 消费前按受控顺序接收两条补充 | 后续请求中的顺序符合准入契约；每条只消费一次；诊断记录能对应接收与消费时刻 |
| P4 | 用 gate 分别固定“接收先发生”和“结束先发生” | 前者按约定完成消费或明确暴露未消费去向；后者明确失败；没有成功后静默丢失、跨轮误投或重复处理 |
| P5 | 工具尚未返回时补充“只分析，别继续扩大范围” | Steer 本身不触发工具取消或重执行；已发生事实保留，后续请求包含补充；单独发 Interrupt 时才走既有取消契约 |

观察字段至少包括 Thread、预期/实际 Turn、输入标识、接收结果、消费位置及捕获的模型请求。使用 gate 控制顺序，不能依靠 sleep 或真实模型偶然遵从证明正确。P4 的未消费去向必须先明确为可断言的本地契约，不能用日志中的“已接收”替代结果。

## 基础不变量

- 子 Agent 使用独立身份与历史，并具有可核对的父子关系；继承背景不等于共享可变执行现场。
- 创建调用的 Output 只回答创建与初始交付结果；子方最终答复不能再作为同一 Call 的第二份 Output。
- 消息入队、进入模型请求、模型采取行动分开观察；消息正文不能自行改变运行时交付模式。
- 同一子方最多一个活动 Turn；不同子方可以独立推进，仍受明确定义的容量限制。
- 模型请求和工具执行遵守子方的有效配置及只读绑定，不能通过委派扩大访问权限。
- 子任务成功、失败和中断均保留来源；状态查询和等待返回不替代业务验收。
- 中断旧任务后的迟到事件不能覆盖新任务状态，也不能造成重复最终结果。
- 关闭和重启不能把已发生事实删除或静默重新执行；未确定的结果不能伪装为成功。

忙时 followup、父 Turn 取消是否级联、邮箱持久化和通知重投策略，须先由目标工程本地契约确定。下面的相关测试按已确认策略断言，不能以“取决于实现”跳过验证。

## 确定性场景

使用 gate、可控模型响应与事件收集器。超时用于防止测试挂死，不以耗时快慢作为正确性依据。

| 编号 | 场景 | 必须观察到的事实 |
| --- | --- | --- |
| S1 | A 创建 B，B 阻塞在模型 gate | A 已拿到创建 Output 并能推进；B 尚无最终结果；不是等待 B 完成后才伪装异步 |
| S2 | B 执行一次只读工具并答复 | B 有自己的 Call/Output 与历史；A 收到关联 B 和任务的结果并进入下一次整合请求 |
| S3 | 创建时不继承父历史 | B 能得到显式任务及有效配置；看不到未交付的父方私有历史；仍具有父子关系 |
| S4 | B 空闲，先发普通消息再触发任务 | 普通消息被接收但没有自行采样；触发后捕获的模型请求包含应消费消息；入队成功没有被写成已读 |
| S5 | B 运行中收到消息与后续任务 | 按确认的消费边界处理；不产生第二个并发 Turn；后续任务归属清晰，无静默丢弃 |
| S6 | 等待遇到消息、完成事件或超时 | 分别报告等待原因；超时不使 B 自动成功、失败或取消；状态查询不声称有业务进展 |
| S7 | 两个子方逆序完成 | 每份结果关联正确子方与任务；父方不会把快者结果记给慢者；单个失败不冒充整批成功 |
| S8 | 创建达到容量上限、创建中途失败 | 超限被明确拒绝或按约定排队；初始化失败不留下可调度的半成品和泄漏名额；清理后可再次创建 |
| S9 | B 运行时中断，随后交付新任务 | 分开观察取消请求与终态；已完成事实保留；旧响应迟到不污染新任务；B 身份保持可解释 |
| S10 | A 的 Turn 结束或被取消，B 尚未完成 | 两条路径分别符合已选生命周期策略；B 的后续结果有明确去向，不凭父 Turn 结束就删除子身份 |
| S11 | 显式关闭 B，再对 B 发消息或派工 | 当前执行按关闭契约收口；资源与名额释放；历史保留；后续操作明确拒绝或按已定义的重建规则处理 |
| S12 | 运行中重启、结果产生后重启 | 持久事实可恢复；未完成状态如实标记；不静默重放旧任务；已记录结果不被重复计作新任务结果 |
| S13 | 无效目标、重复名称、越界配置及邮箱满 | 在执行前按契约拒绝或反馈；不投递给错误 Thread；不扩大仓库访问；失败不破坏其他 Agent |
| S14 | 通知失败或重复、父方尚未消费 | 可区分任务已完成与通知未送达；重复通知不造成重复整合或覆盖；若不保证持久交付，明确暴露该边界 |

S3 若扩展历史继承，补测创建快照不会跟随父方后续消息自动变化，不携带活动句柄、不重登记旧授权，且配对历史仍有效。自动卸载与恢复若另行激活，应补测身份和未消费消息保留，而不是把它混入显式关闭。

## 观察证据

至少能关联父/子 Agent、Thread、任务、Turn 和相关工具 Call；消息有可追踪标识与交付模式。记录创建接收、任务触发、消息接收、进入模型请求、执行终态、通知投递、取消请求和资源释放这些必要边界。

不要求每种观察事件都成为持久化格式。先在本地契约区分持久事实、运行状态和诊断信息，再选择记录位置。测试通过捕获实际模型请求证明可见性，通过 gate 证明执行顺序，通过恢复后的历史证明持久边界。

## 审查时的三个反例

1. 创建工具已经返回，但 B 从未获得执行机会：是否只登记了身份，漏掉初始任务触发？
2. 日志显示消息发送成功，但 B 一直空闲：该操作是否只承诺入队？不能把它直接判为模型不服从。
3. 中断后 B 接到第二个任务，第一轮结果随后到达：系统依据哪个任务标识拒绝旧结果覆盖？不能只用 Agent ID 配对。

每个切片都应同时展示正常路径、失败路径和一个边界场景。退出前还需证明未破坏既有 Call/Output 配对、取消收口、持久恢复与只读工具边界；不要求为文档准备运行工程测试。
