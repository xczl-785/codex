# 0004：取消传播验收材料

本文只固定实践 0004 的行为不变量、场景矩阵和观察证据。实验目标、范围、里程碑与启停条件见[实践任务 0004](../0004-cancellation-propagation-lab.md)。

## 行为不变量

1. Turn 运行时拥有取消源；模型客户端和工具执行器只接收取消信号，不自行决定 Turn 终态。
2. 取消能够唤醒正在等待的模型请求和工具调用。
3. 已经到达结果提交点的调用保持真实结果，不能事后改成取消。
4. 已记录 Call 在取消时仍未完成，必须得到唯一、结构化的取消 Output。
5. Turn 收到取消后，不根据迟到结果发起下一次模型请求。
6. 取消不会回滚已经发生的文件或远端副作用。
7. Call 批次仍先整体记录，所有 Output 通过 `call_id` 唯一配对。
8. 新 Session 只从持久事实重建，不复活旧 Future、令牌或运行资源。
9. UI 和事件订阅者可以发出意图或展示状态，但不拥有运行时终态。

结果与取消竞争必须有明确线性化点。推荐以结果成功进入 Harness 状态提交路径为准，不能以副作用发生、工具线程返回或 UI 收到事件代替。

## 场景矩阵

所有竞态使用 barrier、channel、可控 test double 或显式 gate。

| 编号 | 场景 | 必须观察到的事实 |
| --- | --- | --- |
| C1 | 模型请求尚未返回时取消 | 等待被唤醒；Turn 取消；没有工具调用或下一次采样 |
| C2 | 工具开始前取消 | 已记录 Call 获得取消 Output；工具主体不启动 |
| C3 | 工具运行中取消 | 工具收到信号；未完成调用取消；没有下一次采样 |
| C4 | 结果先到达提交点，随后取消 | 保留成功或失败结果；Turn 不继续采样 |
| C5 | 取消先确认，工具结果迟到 | 只保留取消 Output；迟到结果不产生第二个 Output |
| C6 | 批次前一个完成、后一个取消 | 前一个结果保留；后一个取消；不做整批回滚 |
| C7 | 非致命工具失败后再取消 | 已提交失败保持失败；其余未完成调用取消 |
| C8 | 取消完成后持久化并重启 | 历史与 Turn 终态完整；不重跑工具或恢复旧任务 |
| C9 | 重复取消 | 行为幂等；每个 Call 至多一个 Output，只有一个 Turn 终态 |

## 事件与诊断证据

事件至少表达：取消请求到达、模型或工具开始响应、单个调用以成功/失败/取消收口、Turn 最终取消。诊断信息应携带 Turn、Step 和 call 标识及结构化 outcome。

完成事件可以按真实发生顺序展示；持久化历史按行为契约记录。测试需要证明二者没有因展示方便而混为同一顺序。
