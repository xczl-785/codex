# 0005：并行调度验收材料

本文只固定实践 0005 的调度不变量、场景矩阵和观察证据。实验依赖、范围、里程碑与启停条件见[实践任务 0005](../0005-bounded-parallel-tool-scheduling-lab.md)。

## 职责与不变量

- 模型或上层工作流表达业务依赖；依赖 A 结果的 B 应在后续采样产生。
- Harness 读取工具能力、执行并发上限和共享/独占门禁，并等待整批收口。
- 工具声明自身并发能力并保证内部安全，不决定整批历史顺序。
- 调度器不分析路径、参数或工具名称来猜资源冲突。
- Call 批次在任何工具启动前整体记录，Output 通过 `call_id` 唯一配对。
- 普通工具失败只形成自己的失败 Output，不自动取消兄弟调用。
- 下一次模型请求必须等待所有已启动和未启动调用取得最终结果，并释放批次许可。
- Turn 取消保留已提交结果，取消运行中和等待许可的调用，不回滚外部副作用。

第一版能力门禁：

- `Shared` 可以和其他获准的 Shared 调用重叠，仍受全局上限约束；
- `Exclusive` 开始前等待当前调用排空，执行期间阻止其他调用启动。

建议采用批次输入顺序公平性：Exclusive 到达队首后，不再启动其后的 Shared，待当前调用排空后执行 Exclusive。

## 两种顺序

完成事件反映真实结束先后；模型历史中的 Output 按原 Call 批次顺序稳定记录。慢 A、快 B 因而可以产生 B/A 完成事件，同时形成 A/B 历史。`call_id` 负责配对，稳定位置负责可预测投影。

## 场景矩阵

“慢”和“快”由 gate 控制，不依赖绝对时间。

| 编号 | 场景 | 必须观察到的事实 |
| --- | --- | --- |
| P1 | 两个 Shared，上限 2 | 两者在任一 gate 释放前都进入运行态，证明真实重叠 |
| P2 | 慢 A、快 B | 完成事件 B/A；历史 Output A/B；配对正确 |
| P3 | 三个 Shared，上限 2 | 任一时刻最多两个运行；释放许可后第三个才启动 |
| P4 | 并发上限 1 | 退化为现有串行语义 |
| P5 | Shared A、Exclusive B、Shared C | B 不与其他调用重叠，并按公平性规则获准 |
| P6 | A 失败、B 成功 | B 不因普通失败取消；整批收口后才继续模型 |
| P7 | B 完成后取消，A 仍运行 | B 结果保留；A 取消；不再采样 |
| P8 | 取消时 C 等待许可 | C 不启动工具主体，并获得取消 Output |
| P9 | 批次持久化后重启 | 历史完整、稳定、唯一配对；不重放批次 |
| P10 | 同名调用和异名调用 | 都只由注册能力和门禁决定，不按名称特殊处理 |

## 事件与诊断证据

事件至少携带 Turn、Step、batch、call 标识，等待/获准/开始/完成状态，工具能力，并发上限和最终 outcome。必要时同时记录完成序号与稳定历史位置。

测试不应断言线程 ID 或绝对耗时。它应通过 gate 直接证明重叠、上限、独占、公平性和批次收口。
