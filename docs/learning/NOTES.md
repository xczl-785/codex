## 讲解方式

- 使用中文，先解释职责、数据流、设计动机和失败后果，再引入真实模块、类型与函数。长期学习规则见根目录 [AGENTS.md](../../AGENTS.md)。
- 学习者了解常见工程和 Agent 概念，但不熟悉本仓库大量符号。每次围绕一个可验证的问题展开，用具体场景、复述和必要源码对照确认理解。
- 对话是主要学习载体。答疑时先核对源码并回应连续追问，再沉淀值得长期保留的解释；文档整理不得阻塞当轮回复。
- 架构设计题先给需求、边界与预期交互，允许学习者先反问澄清；不要直接交出某种类型或设计模式作为答案。
- 概念已通过场景校准时提高讲解起点；“了解”或实验资料已创建，均不等于全部实现分支已经验收。

## 实践讲解的深度与边界

- 当前阶段、激活条件和顺序只读取维护账本，不依据旧笔记重新安排实验。实践精确状态仍由独立工程维护。
- [实践 0003](practice/0003-context-history-recovery-lab.md) 区分已经发生的事实如何恢复，以及运行中的 Turn 如何压缩续跑。按其阶段契约验证理解，不把显式 checkpoint 的实现证据当作自动压缩已实现的证据。
- 实验源码与实时进度由独立 CodebaseAgent 工程拥有；开始实现前核对该工程自己的 `docs/STATUS.md`、源码和测试，不在本学习分支复制其文件清单或声称重新验收。
- 核心机制决定阶段是否完成。同生命周期的体验优化只在学习者提出并在目标工程激活后实施；未激活候选不是待办，也不阻塞学习完成。
- 权限控制面与失败语义深入讲解，操作系统沙箱只定位责任和入口。上下文事实、投影、检查点和恢复不变量深入讲解；tokenizer、摘要算法、向量记忆及分布式存储只在真实问题触发时深入。
- Checkpoint 横向比较保持对象边界：文件快照、图状态和会话历史不能直接排名。朋友项目实际采用 LangGraph 还是仅接入 LangChain 仍未确认，涉及其存储的结论继续保持条件性。
- 通过修改源码观察真实进程生命周期属于可选实践，不因历史笔记中的意愿自动激活。

## 后续教学约束

- 转型课程中用户已将权限应用联系到既有知识，并主动提出 agent native 的工具设计视角。介绍具体类前，先交代其在全体操作路径中的覆盖范围；不要把 patch 专用入口讲成所有修改的统一关卡。理解证据见[记录 0019](learning-records/0019-agent-native-tools-and-common-permissions.md)。

- Subagent 采用设计目的 → 工作关系 → 创建与执行链的讲法后，用户明确反馈清晰。新机制先讲谁触发、何种场景、状态怎样改变，再引入术语。
- 用户允许加快已理解内容，但不省略新概念的因果链，不连续小测，不让边缘例外阻塞主线。按需用操作、返回效果和同步/异步边界表辅助。
- 通信保持发送模型、运行时、接收模型三层职责。用户已推导出交付成功不保证模型读到；不再从头反复解释两个工具。
- 用户希望逐课标注难度与记忆深度。沿用记录 0015 的证据等级，不以反复提问次数断言遗忘，教学不准确造成的追问不能归因于学习者。
- Skills 加载和 MCP 接入是明确兴趣；Skill 设计想法到对应主题再问，不自动成为实现任务。MCP 后保留内部工具 / Skill / MCP 横向对比。
- Skills 要尽可能全面覆盖使用、设计、运行机制与接入实践，按路线图的八个知识单元推进。用户以 `$agent-docs` 和外部文件变化后的候选刷新追问具体链路；后续继续用可观察场景区分界面目录、Turn 快照与模型正文，避免笼统使用“加载”“扩展”“片段”。理解证据见[记录 0018](learning-records/0018-skills-loading-and-refresh-baseline.md)。
- CodebaseAgent 转型要作为课程学习：Skills 接入实践完成后才开课，在当前学习仓库先讲清目标、权限与编码闭环，学完再编写实践任务书，之后按独立工程流程实践。开课条件与当前衔接以维护账本为准，不能把转型意向当成立即实施授权；范围见[路线图](roadmap.md#codebaseagent-转型课程与实践)。
- A2A 扩展已满足当前需要；OpenCode 委派 Skill 仅作概念映照，不启动委派或新增实现计划。
- durable sleep 生产触发链路和 App 专用跨 Thread 工具仍有证据空白；标注未知，不靠假设补全。

- Skills 涉及上下文的机制较多：用户理解思路但感到难记。按发现、选择、上下文、执行四条主线串联；复习时沿用整体回顾连接机制，不强求背符号，也不立即重讲整套课程。
