# Teaching Notes

- 使用中文和通俗表达，先讲职责、数据流和类比，再介绍真实符号。
- 用户理解常见工程与 Agent 概念，但不熟悉本仓库的函数名和模块名。
- Subagent 生命周期与通信、Thread 拉起与交互是优先专题，不是全部课程范围。
- 以静态源码阅读为主，不要求在本机编译或运行仓库。
- 每课只解决一个小问题，并提供简短的回忆练习。
- 课程和速查资料使用纯 Markdown，不制作 H5 或样式资产；优先保证对话响应速度，只沉淀值得长期保留的结论。
- 每轮采用“先用当前源码核对事实 → 立即回答用户 → 回答后再做简洁沉淀”的顺序；文档整理不得阻塞当轮答复。
- 对话是主要学习载体，应提供较完整的解释；`lessons/` 也要保留足够细节，使用户脱离聊天记录后仍能独立回顾和理解。`reference/` 才负责压缩为速查内容。
- 讲解架构概念时固定覆盖“是什么、为什么这样拆、解决什么问题、不这样做会怎样”，设计动机优先于名词和包含关系。
- 架构设计题必须先给出需求、边界和预期交互，允许并鼓励用户先反问澄清；当前安全审计设计题结束后，切换为用户围绕 Thread、Session、Turn、Task 主动提问、教师结合源码回答的形式。
- 已在第九课区分运行时模型历史、追加式 rollout、App Server 的 Turn/ThreadItem 与 TUI transcript；后续不得把 `replace_compacted_history` 理解为抹除 Thread 的全部历史。
- 用户已主动把 Codex 多层持久态/运行态隔离与 Harness 状态外置联系起来，后续可沿“事实来源与可重建投影”继续讲解。
