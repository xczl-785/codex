# 文件变化、部分失败与历史重建

本课回答：修改已经获得许可之后，怎样理解内容冲突、部分修改、撤销和依据历史重建？建议难度高，重点在状态与证据边界。承接[课程 0031](0031-coding-agent-tools-and-permission-boundaries.md)，本文保存已讲内容，不规定目标工程的并发控制或恢复实现。

## 1. 许可与适用性是不同问题

Agent 读取函数后构思补丁，用户在补丁提交前又修改文件。此时路径与授权未变，权限检查可能通过，但修改依据已经过时。局部补丁通过上下文和旧内容定位替换区域，相比用旧版本整体覆盖，能减少覆盖无关修改的机会。

当前 [derive_new_contents_from_chunks](../../../codex-rs/apply-patch/src/file_update.rs) 读取当前文件，计算替换并生成新内容。找不到预期上下文或旧行时返回错误。用户改动无关位置时可能正常应用；修改目标区域时可能失败；业务语义变化但目标文本仍在时，补丁也可能成功，却不再符合需求。

[seek_sequence](../../../codex-rs/apply-patch/src/seek_sequence.rs) 先精确匹配，再尝试忽略部分空白与规范化部分字符。它服务于补丁定位，不是完整文件版本校验。工具读取当前文件与最终写入之间仍需考虑并发；不能从“执行时读取”推导出原子读改写或完整事务保证。锁、版本条件等是进一步的设计选择，本课未确认 Codex 所有路径的并发保证。

应分开判断：是否允许修改、补丁是否适用、修改是否实现任务目标。匹配失败后重新读取并理解变化，不能仅为让工具成功而退回整文件覆盖。

## 2. 为什么设计要分开这些维度

用户观察到权限、沙箱、Thread、Session、工具调用等都在拆分角度。可用关注点分离理解，并联系单一职责、高内聚低耦合与正交设计。这是分析方法，不是宣称整个 Codex 严格采用同一个模式。

判断边界的实用问题是：A 改变时 B 是否可以不变，A 结束后 B 是否仍然存在？审批变化不要求改变补丁格式；工具调用返回不代表进程退出；执行失败不代表副作用消失。这些独立变化或生命周期提示需要分别表达。分开建模不要求每个角度建立一个类，也可以使用字段、函数或模块；避免为了纯粹机械增加复杂度。

教学会主动展开概念，真实源码仍可能有历史兼容与折中。不能将讲解的清晰结构等同于整个工程已经实现理想分层。

## 3. 部分失败与撤销

补丁修改 a、b 后，在 c 上失败，会同时存在“操作未完成”和“部分文件已改变”两个事实。[ApplyPatchFailure](../../../codex-rs/apply-patch/src/lib.rs) 同时保留错误与实际变更信息，调用方不能只根据失败标记断定没有副作用。

撤销需要考虑变化归属和当前状态。时间线为用户原有修改 U → Agent 修改 A → 用户后续修改 B 时，撤销 A 通常需要保留 U 和 B。恢复 Agent 开始前的完整文件会丢失 B，恢复 Git 提交版本还可能丢失 U。反向局部修改也可能与 B 冲突，需要核对实际内容；无法确定实际变化时，先检查，不能宣称安全自动撤销。这里描述撤销所需条件，不声称 Codex 对全部工具提供统一副作用撤销。

## 4. 丢弃文件修改后，为何 Agent 可能从历史还原

用户反馈曾误 checkout 或丢弃变更，Agent 表示可以依据历史恢复。未查看那些具体实例，不能断言每次使用相同方式。常见路径是：文件修改被丢弃，但会话中的工具调用仍保存了补丁、写入脚本或曾读取的内容。Agent 核对当前文件，再按历史依据重新应用或构造修改。这可能使用普通修改工具，不必存在专门的历史文件恢复接口。

工具输入常比“修改成功”的输出更有恢复价值：输入包含修改内容，输出可能只有文件名与状态。调用记录表达请求，仍须结合结果区分成功、失败与部分完成。脚本依赖外部输入、输出截断、用户修改未记录等情况都会限制恢复能力。

当前 [Session::record_conversation_items](../../../codex-rs/core/src/session/mod.rs) 将项目记录进运行历史，并转换为 RolloutItem 持久化。[rollout policy](../../../codex-rs/rollout/src/policy.rs) 保留 FunctionCall、CustomToolCall 及对应输出。[recorder](../../../codex-rs/rollout/src/recorder.rs) 按配置的 Codex home 建立 `sessions/YYYY/MM/DD/rollout-….jsonl` 路径。这是当前 Core 本地源码行为，不代表所有客户端使用同一可访问位置。

磁盘保存不等于模型当前可见。刚发生的修改可能直接在上下文里；压缩后可能仅剩摘要，精确恢复可能需要有权限、有工具重新读取原始记录。只有功能摘要时，重写相同功能属于重新实现，不能承诺字节级恢复。

[TurnDiffTracker](../../../codex-rs/core/src/turn_diff_tracker.rs) 依据当前 Turn 已发生的补丁变更计算净文本差异，并非工作区永久备份，也不覆盖全部外部程序写入。会话历史、差异跟踪、当前工作区和 Git/其他备份分别承担不同职责。
