# 子 Agent 写入：执行约束、模型协调与结果交付

本课回答：子 Agent 能改代码后，Harness 实际提供什么，哪些协作问题主要由模型管理？建议难度中高，重点区分执行能力、任务约定和整体判断。承接[验证职责](0033-verification-tools-and-model-judgment.md)，不为 CodebaseAgent 预设文件锁、独立工作区或自动合并方案。

## 1. 三种不同安排

场景：主 Agent 将接口实现交给 A，测试交给 B。

| 安排 | 含义 | 落实者 |
| --- | --- | --- |
| A 改实现，B 改测试 | 任务分工 | 主模型安排，子模型理解与遵守 |
| A 只能写实现目录 | 资源权限 | 宿主与执行设施 |
| A、B 使用独立文件副本 | 工作区隔离 | 工作区管理与执行环境 |

任务消息不会自动成为路径权限，也不会自动复制工作区。独立 Thread 表达独立上下文与运行过程，不保证文件隔离。

## 2. 当前 Codex 链路提供的机制

[prepare_agent_spawn_config](../../../codex-rs/core/src/agent/child_config.rs) 从父级有效配置构造子配置，并通过 `apply_spawn_agent_runtime_overrides` 接续当前 Turn 的审批策略、工作目录与权限配置。[thread_spawn](../../../codex-rs/core/src/thread_spawn.rs) 的创建请求还传递 Step 的环境快照。

核对的 [V2 spawn 参数](../../../codex-rs/core/src/tools/handlers/multi_agents_v2/spawn.rs) 包括任务消息、名称、角色、模型与历史派生方式，没有按任务分配文件写入范围的参数。这支持“这条常规委派链路不自动将分工变成写入限制”，不据此断言所有客户端和部署都没有隔离机制。

内置 [worker 角色描述](../../../codex-rs/core/src/agent/role.rs) 要求明确文件或模块责任、告知 worker 代码库中有其他参与者、不要撤销他人修改。这些是模型指令，不是路径权限或文件锁。

因此，当环境允许写入整个项目，主模型说 A 负责 src、B 负责 tests 时，A 写 tests 可能违反分工却仍处于有效权限内；访问项目外受限资源则可能被执行机制拒绝。Harness 的执行边界不等于模型划定的任务边界。

Harness 提供创建与运行、配置和环境传递、消息与状态、等待与中断、工具执行及既有权限约束。模型负责分工、安排依赖、协调接口变化、判断集成结果。要把分工变成硬约束，需要额外落实身份对应写入范围或工作区隔离，不能仅依赖提示词。

## 3. 共享工作区中的三类冲突

文件冲突是两者根据旧内容修改同一文件；接口冲突可能发生在不同文件，例如 A 改为返回可选值，B 仍按旧返回类型编写测试；验证干扰则是测试运行时其他 Agent 仍在修改代码。文件锁不能自动解决接口语义不一致。

主模型应先协调接口约定，再分工；约定变化后通知相关参与者。这属于合理的模型行为，并非已经确认由 Harness 强制执行。局部测试分别通过也不能直接证明最终组合状态通过；主模型需要根据组合后的变化补齐必要证据，而不必机械重跑全部检查。

## 4. 子 Agent 完成后，交付了什么

[InterAgentCompletionMessage](../../../codex-rs/core/src/context/inter_agent_completion_message.rs) 组织任务名称、发送者和正文，形成主模型可读取的完成消息。这个消息结构不强制附带完整补丁、测试日志或代码版本，也不验证正文中的业务结论。

Harness 组织与交付信息，子模型报告工作，主模型判断整体是否满足目标。核查重点是接口连接处、重要结论与不确定性，不要求把子任务全部重做。

共享工作区中，文件可能在报告到达之前已经改变：修改 → 主 Agent 能读到变化 → 子 Agent 验证 → 完成报告。等待完成通常不是等待一份尚未应用的代码包；拒绝报告也不代表修改没有发生。独立工作区或补丁交付可以分开产出与应用，但需要明确安排。

## 5. 结果归属与整体判断

最终 diff 表达工作区相对基线的变化，不一定说明每行由谁修改。用户先改一处，A 改另一处，B 再调整 A 的内容时，文件分工不能代替实际变更归属证据。

当前文件提供最终状态，各子 Agent 工具记录提供其请求与结果，完成报告提供模型总结；三者可以互补，不能互相替代，也不保证已具备覆盖任意命令副作用的精确审计。

A 完成实现、B 完成测试后，主 Agent 仍可能发现遗漏的调用方。局部完成并不推出全局完成。主模型持有总任务，需要检查局部成果连接和最终证据；Harness 不会仅凭完成通知自动证明整体正确。

## 6. 本课的教学纠正

用户明确反馈实际使用中主要由主 Agent 管理修改面，与前一课验证职责问题相同。后续必须按“当前 Harness 保证 → 模型使用方式 → 可选新增工程机制”讲解，不把应解决的问题描述成现有代码已经提供的保证。

转型剩余收尾为只读与编码模式的运行契约，以及超时、取消、结果未知和恢复不盲目重放的编码场景串联；完成整体回顾后再整理实践输入。
