# Skills 接入：从一次请求确定职责与验收边界

本课将前面机制映射为 CodebaseAgent 的接入设计输入，不声称目标工程已实现这些接口，不修改其现有只读契约，也不替代后续实践任务书。参考链路为[发现快照](../../../codex-rs/ext/skills/src/host_snapshot.rs)、[显式选择](../../../codex-rs/skills/src/selection.rs)、[正文加载](../../../codex-rs/ext/skills/src/host_prompt.rs)与[Turn 接入](../../../codex-rs/core/src/session/turn.rs)。

## 1. 一次请求的链路

用户要求用 recovery-analysis 分析仓库恢复机制。宿主根据工作目录及配置取得清单，解析明确选择并定位资源，读取正文形成上下文，与用户输入、历史和工具定义一起发送。模型再按方法使用现有工具，结果进入历史并驱动后续采样。

Skill 接入新增的是发现和指令加载职责，执行仍使用已有 Agent 循环。它不自动生成一个运行 Skill 流程的确定性状态机。

## 2. 五项职责

| 职责 | 输入与输出 | 必须明确的边界 |
| --- | --- | --- |
| 发现 | 工作目录、来源配置 → 元信息清单及诊断 | 身份、名称、位置、启用与隐式策略；坏包不能让用户无从解释 |
| 选择 | 用户输入、清单 → 明确资源 | 路径绑定、名称歧义、禁用、失效选择 |
| 加载 | 明确资源 → 正文或读取错误 | 来源、长度策略、重复注入、文件变化 |
| 上下文接入 | 清单与正文 → Provider 支持的消息 | 区分候选与已选正文；刷新、历史、压缩契约 |
| 执行 | 模型调用 → 真实工具结果 | 既有工具、权限和环境限制继续生效 |

这些是职责，不要求机械地建立五个复杂类或照搬 Codex 扩展框架。实现组织应依据目标工程现有边界决定。

## 3. 身份和一致性

界面显示名称，提交应尽量绑定路径或资源 ID。纯文本选择需要明确唯一匹配、同名歧义、禁用与删除的结果。显式失败不能静默换成另一个同名包。

发现快照也不必然冻结正文：若只保存路径，之后再读文件，可能读到变化后的内容。需要严格版本一致性时必须额外定义内容快照或版本校验，不能仅凭类型名带 Snapshot 就认为已经解决。

正文过长应明确拒绝、截断或分段策略；读取失败不能报告“已使用”。同次输入重复选择同一资源应避免重复注入。

## 4. 上下文与能力边界

候选清单回答“有哪些可选方法”，正文回答“本次方法是什么”。普通 Responses 或 Chat 也能承载它们，不要求先实现 Responses Lite 或完整 world state。应先明确何时刷新清单、变化怎样告知模型、正文怎样进入历史及压缩后何时重读。

Skill 若要求执行当前 Agent 不具备的脚本或写入动作，应报告能力缺口。不得为了让 Skill 跑通而暗中扩大工具和权限范围。Skills 实践不等于提前开始标准 code agent 转型。

## 5. 不要合成一个含义模糊的 loaded 状态

| 状态 | 表达什么 |
| --- | --- |
| 发现结果 | 系统知道哪些资源 |
| 本次选择 | 本次输入选中了哪些资源 |
| 已读内容 | 哪些具体文本已进入历史 |
| 使用事件 | 哪些读取或执行请求被识别为 Skill 行为 |

已发现可以未选用，已选中可以读取失败，已读正文可以尚未执行，登记使用也可以执行失败。界面和日志应保留这些区别。

## 6. 验收场景

正常显式使用应验证正确正文进入请求；自主选用应验证描述是否帮助模型选对且不过度触发；同名、失效路径和禁用不能选错。变化场景验证清单更新与正文重读是否符合契约，历史场景验证工具往返和压缩后的实际可见性，执行场景验证 Skill 不绕过只读与权限边界。

解析、去重和消息结构适合确定性测试；模型选择质量与任务效果需要真实案例。不能用“模型回答了”作为全部接入验收，也不能用模型表现代替协议结构测试。本课尚未运行这些验收。

## 7. 子 Agent 的三种来源不能混淆

历史或任务文本决定子 Agent 能否看到父 Agent 已读正文；子 Agent 自己的配置、工作目录与资源来源决定能否发现、重读 Skill；工具、环境和权限决定能否实际执行。继承一段脚本说明不代表脚本存在，也不代表具备执行能力。没有继承历史也不代表无法自主发现同一 Skill。

当前 Codex 的[角色配置](../../../codex-rs/core/src/agent/role.rs)可限制 Skill，[对应测试](../../../codex-rs/core/src/agent/role_tests.rs)覆盖角色禁用指定包。禁用选择不等于清除继承历史中的正文。委派依赖某个 Skill 时，应交代方法或资源并保证接收方可取得，不能凭父 Agent 使用过来推定子 Agent 也可使用。

## 8. 远端来源与插件

本地与远端共享发现、选择、读取、上下文和执行主链，但身份与访问机制不同。[SkillProvider](../../../codex-rs/ext/skills/src/provider.rs)通过 authority、package、resource 和读取 context 保持来源边界；列出的资源必须由对应来源读取或搜索，不能把不透明 ID 随意解释为本地路径。authority 表示来源路由身份，不代表更高指令权限。

[read_main_prompt](../../../codex-rs/ext/skills/src/extension.rs)按来源选择 Host、Executor、Cloud 或 Custom 上下文；执行环境不可用时报告错误，不静默改用本机文件系统。远端 references 也应在同一来源和包中解析，不能误读工作区同名文件。本地文件监听不自动覆盖远端刷新，具体缓存契约由来源负责。

插件是打包与交付维度，本地/远端是访问维度。插件安装到本地后，所带 Skill 可以由本地文件读取。Skill 声明工具依赖不等于工具已接入或已授权；缺失能力要明确报告。
