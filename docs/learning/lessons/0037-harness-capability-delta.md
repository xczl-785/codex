# 0037：从只读 Agent 到编码 Agent，Harness 需要补充什么

## 问题与范围

前面课程描述了编码流程，但用户指出：模型判断与 Harness 能力混在一起，不能据此看清工程要增加什么。本课独立整理职责增量。

目标场景是修改绑定仓库中的代码、执行检查，并向用户交付实际修改和验证依据。以下现状依据 2026-10-28 对 CodebaseAgent 能力文档及 `src/tools/mod.rs` 的针对性静态核对，不是完整源码审计或测试重验。建议增量不是已批准的实施范围；目标工程的当前事实仍由自身文档和实现拥有。

## 1. 已有基础：复用，而不是重造循环

| 现有基础 | 编码时的用途与限制 |
| --- | --- |
| Model—Tool 循环、工具声明与注册 | 接入修改和执行工具，不需要另造编码循环 |
| Call/Output 因果、失败回传 | 将新工具结果交回模型判断 |
| Thread/Session、历史、上下文压缩 | 承载编码过程的上下文 |
| 持久事实与恢复 | 复用结果未知、不自动重放旧调用的语义；不等于文件备份或进程恢复 |
| 并发声明、工具调度与协作式取消 | 复用准入和取消入口；不等于已有 OS 进程终止能力 |
| 仓库绑定、路径检查和四个读取工具 | 继续定位与读取；不等于通用命令沙箱 |
| 子 Agent、通信与 Skills | 继续复用；存在子 Agent 不意味着必须立即开放子方写入 |
| TUI 活动展示与诊断 | 接入新操作的状态与结果 |

当前仓库工具为 list_files、find_files、search_text、read_file；Skills 工具接入不自动带来 shell 执行。只读工具的路径检查控制经这些工具发生的访问，无法替代对任意脚本、子进程资源访问的约束。

## 2. 新增或扩展的职责

| 增量 | Harness 应提供的确定性行为 |
| --- | --- |
| 文件修改入口 | 解析和执行修改，明确匹配失败、写入失败及部分完成；返回实际结果 |
| 写入授权与路径约束 | 决定能否写、可写范围，在操作处落实；处理新路径、链接和保护对象 |
| 命令执行与进程管理 | 工作目录与环境、输出限制、退出状态、超时、取消、资源清理 |
| 执行权限落实 | 让文件、网络等真实访问符合所承诺的权限，覆盖开放的操作路径 |
| 修改观察 | 给模型与用户提供受影响文件和实际差异；不必先实现复杂 UI |
| 有副作用工具调度 | 明确写入能否并行、约束作用域和取消后占用；不能仅从 Exclusive 名称推断工作区锁 |
| 写入与执行的历史、恢复 | 区分未开始、已完成、部分完成和结果未知；不将失败等同于未修改 |
| 工具说明与运行指令 | 准确说明能力、权限和失败含义，调整原有只读工作规则 |

这是一组责任，不是八个必须新增的模块。具体组织应复用既有工具、历史和调度设施。写入接口也不必照搬 Codex 的 patch 格式。

若仅开放受约束的编辑工具，可以在该入口落实写入边界；开放通用 shell 后，脚本也能写文件或启动其他程序，权限就必须覆盖相应执行路径。是否用特定 OS 后端取决于目标平台和威胁模型，不能仅靠命令字符串检查宣称已提供沙箱隔离。

## 3. 留给模型的判断

定位原因、选择方案、生成补丁、选择检查、解释验证覆盖、分派任务和决定后续恢复动作，仍属于模型判断。Harness 提供可靠的操作与事实。

“先读再改”可以是工作指令；如果要求强制防止旧内容覆盖，就需要写入前置条件检查。“交付前测试”可以是工作要求；如果必须阻止未满足条件的交付，就需要明确门禁。不要把工作指令误记成已经实现的程序保证。

## 4. 暂不作为转型前置条件

- 完整 Plan 模式与专用规划界面。
- 子 Agent 并行写入、每人独立 worktree；可以先保持子方只读，但选择该边界时要真实落实。
- 自动撤销、全仓快照、跨文件事务；先保证变更可观察、失败表达准确。
- 任意命令自动安全重试、跨重启恢复进程、后台任务中心。
- 专用测试选择器、通用验收引擎、自动 Git/PR 交付。
- 全平台完整沙箱体系；当前开放路径仍须有与承诺一致的权限约束。

这些是本轮不必追求的完整性，不表示永久不需要，也不自动形成目标工程的 Deferred 条目。

## 5. 前置缺口与学习顺序

用户随后指出权限与沙箱尚未正式接入。路线图已经明确：[实践 0002](../practice/0002-permission-sandbox-lab.md)完成于独立 PermissionSandboxLab，其状态机、替身及约定范围不能作为 CodebaseAgent 已完成正式接入的证明。

据此将权限接入与编码实践分开教学、形成任务书并验收，两项均在 CodebaseAgent 内推进。权限专题先补齐公共准入位置、编辑与进程的执行边界、审批结果与实际授权、平台设施和失败语义；以一条真实受限执行路径为目标，不追求完整多平台体系。权限接入验收后，再进入编码实践。

用户随后要求提前准备[编码任务书 0008](../practice/0008-coding-agent-integration.md)，其状态为等待前置验收。材料提前形成不代表实施提前启动，也不意味着先开放无约束执行再补安全。

当前目标工程仍保持原有只读契约。本学习记录不修改其使命、门禁或实现计划。
